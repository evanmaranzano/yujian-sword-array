## 一、总体结论

### 1.1 一句话判断

**C1（"以第一个锁定的人为准"）的需求级冲突已经解除：会话锁算法正确、两版逐行等价、19 项确定性测试实跑全过、换人跳变伪造齐发的主路径被确实封死。系统仍是一个完成度较高的 demo，但距离"7×24 无人值守正式开展"仍差一整套现场可行性验证、故障自愈、部署运维与量化验收层——且新锁本身在 3–5m 现场条件下还有 3 个残余盲区待真机检验。**

### 1.2 C1 修复评估（本轮重点复评）

**做对并经对抗验证确认的：**

- 两版锁（`web/js/lock.js` 135 行 / `yujian/lock.py` 133 行）状态机、阈值、不等号、输出语义**逐行等价**；7 项锁参数 + `handLostTimeout` + 平滑/窗口参数两版逐项同值（V1 核对表全 ✓）。
- "只喂已接受帧"接线正确：Web `_consumeLock` 严格按 `accepted` 喂 SwipeDetector、`reset` 先清历史后喂点（`tracking.js:172-184`）；Python 用 `(session_id, vel_reset_seq)` token 重建检测器（`main.py:107-113`）。换人跳变在原理上无法进入速度历史，**伪齐发主路径封死**；`lock_check` 第 9 组实证驻留吃掉起手 0.2s 后两记挥手仍各触发一记、方向断言正确。
- 正常挥手不可能被误拒：0.22/帧的跳变阈值对应 30fps 下 6.6 归一化/s（4m 处约 30 m/s），真人快挥（≤8 m/s）余量 4–10 倍（lock_check 0.8/s 快挥零拒绝实证）。
- 大掌帧（凑近镜头）不更新 `lastT`，连续糊镜头 0.5s 正常释放；acquire 直接吸附不长滑；candidate 出区/跳变立即作废。
- 本机实跑 `python -m tests.lock_check`：**19/19 [OK]，LOCK CHECK PASSED，退出码 0**；6 个 JS 模块 `node --check` 全过。

**新锁的残余缺口（详见 §三/§四，均为本轮新发现）：**

| 缺口 | 级别 | 一句话 |
|---|---|---|
| 锁超时是"帧驱动"不是"墙钟驱动"：相机冻结/读帧失败/同帧卡死时，0.5s 释放永不触发，locked 态永久锁存 | 高（与 H2 同根） | 安全网在最需要它（相机故障）时失效 |

## 三、会话锁专项结论（C1 复评，V1 全部回源码验证）

### 3.1 锁状态机本身：正确

empty→candidate（中心 ROI 内见手）→locked（区内连续驻留 0.20s 且帧间连续）；locked 后跳变 ≤0.22 关联、掌尺度 >0.40 拒绝、0.5s 无接受帧释放；空档 >0.07s 输出 `reset` 清速度历史。19 项测试覆盖驻留/区外/跳变拒绝/0.2s 内夺控失败/锁定者回来恢复/超时释放/新人新会话/遮挡保持/远处重现拒绝/大掌/30fps 快挥/reset/联动齐发。两版参数 8 项逐项一致。

### 3.2 残余问题（按严重度）

**L1【high，与 H2 同根】锁的存活判定是"帧驱动"：视频帧停摆时，锁的时间也停摆。**
- Web：`lock.update` 只在 `tracking.js:150` 视频新帧门控内调用；USB 掉线/冻结（currentTime 停）后 `lock.js:107` 的 0.5s 释放逻辑没有执行机会，`present` 永久锁 true；`_publish`（:167，门控外）每 rAF 继续发旧态 → 本命剑定格、aura 保持冻结高速、待机永不恢复、HUD 持续"追踪 30"。
- Python 两条路径：①`cap.read()` 失败 → `continue` 不 tick 锁（`tracker.py:103-110`）；②**读帧成功但画面冻结（驱动挂起重复返回同帧）→ jump=0 持续 accepted、lastT 持续刷新，锁永不释放**（V1-N2，推演 10s 仍 present；这条不受"修 read 失败分支"覆盖）。
- candidate 态冻结则表现为永远锁不上。修复方向：墙钟驱动的"最近有效帧龄"看门狗（门控外判 stale → 强制 seen=false 走一次释放/故障态），Python 侧加帧内容/帧号冻结检测。

**L2【medium】candidate 冻结后恢复首帧"瞬时成熟"。** 驻留判据（`now-candStart≥dwell`）在候选分支内、TTL 作废在函数尾部；冻结期间 candStart 陈旧，恢复首帧手仍在区内即直接 acquire（推演：真实驻留仅 0.10s、冻结 0.3s 后首帧即锁定）。触发窗口窄（须恰在 0.2s 驻留窗内冻结），修 L1 时一并消除。配套小问题 **V1-N1**：候选中断 >TTL 后紧接的检出帧会先刷新 lastT 再判 TTL，TTL 被架空（与注释"中断超过 TTL 重新开始"字面不符）。

**L4【high 影响 / medium 概率】0.22 关联是纯位置泡，无身份特征。** locked 态唯一判据是帧间掌心跳变 ≤0.22，接受即链式更新 lastX/Y（可被小步拖拽到任意位置）。推演：锁在 (0.5,0.5)、遮挡 0.2s（<0.5s 宽限）后另一只手在 (0.70,0.5) 出现（跳变 0.20）→ accepted、**session 不变、不重新驻留**（reset 会清速度历史，故无假齐发）。物理尺度：0.22 归一化 = 3m 处 0.76–0.92m、5m 处 1.27–1.54m 半径。两类现场场景：①儿童凑到体验者手边/两人手在画面中相距 1m 内同时伸手，MediaPipe 重检测边界切到邻近手后可逐帧"漂移移交"；②前人走开、后人 0.5s 内站到同一位（轮流体验极常见）→ 新人不经驻留即时获控。头注释"下一位重新走驻留确认"仅在满 0.5s 释放后成立。建议：用 H1 标定数据收窄 jump（真人 30fps 帧位移约 0.03–0.08，0.22 余量过大，可试 0.12–0.15）；宽限内重现要求连续 2–3 帧匹配再恢复；加掌尺度缓变辅助；预览窗 ROI 框 + acquired 反馈让夺控可被巡场察觉。

**L5【medium，待实测】驻留对闪烁脆弱。** TTL=0.15s 在 30fps 仅容忍连续 4 个丢帧（0.133s），第 5 丢帧（0.167s）作废；出区/跳变帧立即回 empty。推演"2 检出 + 5 丢检"循环（约 30% 检出率）3 秒内 acquire 次数为 0。与 H4（远端小手漏检）直接耦合——驻留用墙钟连续时间而非"累计在区帧数"。建议改计数式驻留（窗口内 M/N 帧在区内即锁定）或 TTL 放宽到 0.25–0.3s，两版同步并重跑 lock_check。

**L6【medium，待实测】ROI y1=0.90 对高机位近距矮儿童不友好。** ROI 仅在获锁阶段判定（locked 后不再判 ROI，本身正确）；但按相机高 1.9–2.2m 水平取景推演，3m 处 y=0.90 对应地面以上仅 0.86–1.16m，1.1m 儿童低挥手可能永远在区外。需现场标定时实测成人/儿童掌心 y 分布再定 ROI 与机位俯仰（建议给"相机光心 1.5–1.7m、略俯"安装口径）。

**L7【low-medium】gap-clear 0.07s 恰在 30fps 单丢帧间隔（0.0667s）之上**：丢 1 帧不清速度历史，重检测抖动 Δ≈0.09（3m 约 0.31m）经 0.12s 窗口即达 swipeHi；丢 2 帧（0.10s）才清。建议改按丢帧计数或阈值降到 0.045–0.05s，待 H1 采抖动分布后定值。

**L3【medium，文档失实+两版分叉】M 翻镜像 Python 真机不释放锁。** `main.py:87-88` 的 reset 只对 headless 的 `_app_lock` 生效；HandTracker 无 reset 方法。实测机理细化（V4）：翻镜像后坐标跳变 >0.22 被连续拒帧，约 0.5–0.7s 后被动超时释放。`HANDOFF.md:82`"两版 M 翻镜像都释放会话"对 Python 真机不成立。

### 5.3 渲染与性能（D3/V3，除 H5 外）

- **D3-06【新，中】7 处 CanvasTexture 全部未设 `SRGBColorSpace`**（scene.js:14,24,33,147,186；swords.js:269,368）：sRGB 字节被当线性值进 HDR RT、OutputPass 末端再编码一次，贴图整体被抬亮（暗部最显著，与"压暗夜景"注释意图相反），bloom threshold/afterimage 截断点都偏离设计；hex 剑色不受影响。修复后需全面重调暗色等级。
- Afterimage damp=0.82 按帧衰减无 dt（vendor 实证 deltaTime 入参被注释忽略）：衰减到 0.1 需 11.6 帧 → 60fps 残影 0.19s、30fps 0.39s，掉帧时拖尾更亮更糊，性能↔观感劣化耦合。建议 `damp=pow(0.82, dt*60)`。
- dt 裁 0.05 而 `clock.elapsedTime` 用未裁真值：相位动画与物理失步；挂起恢复后 Afterimage 持久 RT 留旧帧产生 ~0.2s 鬼影、立即触发一次 80 剑扫荡。建议统一 simT 时钟 + visibilitychange 清拖尾。
- 截图键 S 在 rAF 外、未开 preserveDrawingBuffer，Chrome 下大概率黑图；4K/8K 同步回读编码卡顿 0.1–2s。
- 预览窗真机永久显示（176×132、opacity .85，无开关无 ROI 框）；HUD 字号固定 CSS px，物理尺寸随 Windows 缩放漂移（4K@100% hint 仅屏高 0.93%）。
- 每帧 DOM 写（flash parseFloat、hint/stats 每帧 textContent）；M 键后 #status 文案永久污染无恢复路径。
- CPU 侧很轻（1500 槽全扫 + 228KB/帧实例缓冲上传，JS <0.5ms，瓶颈全在 GPU 填充）；instanceColor 缓冲漏标 DynamicDrawUsage；dpr 热切换 renderer/composer 不同步；!ready 初始化数秒内空跑完整后处理；超宽屏 aspect>2.41–2.96 时远山/天空/暗角盖不住露底色；震屏白噪声低帧频下发粗。
- 清理项实证：sparkLife 只写不读；group.renderOrder=3 死设置（不向子 mesh 传播）；透明剑芯未关 depthWrite（穿剑瞬间轻微层级翻转）；死亡点 y=9999 依赖 frustumCulled=false；出界回收 |x|>45/|y|>30 远大于可视界（屏外剑白跑 1–2s）；Rings fallback 不可达（docs/02 旧结论翻案，无需改）。

### 5.4 引导体验与合规

- **字号 4m 张角实测不足**：110 寸 4K 屏高 1.37m，hint 20px@150% 缩放字高 19mm → 4m 仅 **0.27°**（100% 缩放 0.18°），中文可读门限 0.5–1°；标题 34px@150% 也仅 0.46°。全程两句文案、无站位引导、无挥手示范、无锁定归属反馈（acquired 未消费）、预览窗无 ROI 框。建议待机大号动效（≥屏高 5%）+ 挥手剪影 + 站位光区 + 锁定一次性反馈 + 字号改 vmin/clamp。
- "万剑"口径：单记 64 剑、交互峰值并发 ~360（待机 ~215），容量 1500 余量极大；3–5m 目检密度前不要轻信"无数"观感，加大 swordsPerSwipe 对 draw call/显存几乎零成本。单场景 + 9s 循环 + 单音效，长时间观看重复感（二期）。
- 合规：全仓无 LICENSE/NOTICE；MediaPipe bundle grep 许可串零命中（Apache-2.0 要求随附许可证+NOTICE）；three 保留 MIT SPDX 头但 jsm 插件无许可头；sword-control 仅注释署名无 MIT 原文。字体为系统字体未嵌入（不构成再分发，但"版权归甲方"不覆盖系统字体 IP，LTSC 精简系统可能缺楷体导致视觉漂移；建议改 OFL 楷体或书面澄清）；交付 md"无第三方素材，无版权问题"表述过宽。
- 可复现：无 requirements.txt/锁文件、工作区无 .venv、README 无建环境步骤（mediapipe 1.0.1 经前序核实 PyPI 真实存在、支持 3.9–3.12 无 3.13/3.14 wheel）；vendor 无 VERSION/sha256 清单。MIME 本机 3.14 实测 .mjs/.wasm 正确（旧担忧基本排除），但启动器不锁定解释器版本。
- http.server：绑 0.0.0.0、无 /healthz、日志不落盘、无端口治理；建议 --bind 127.0.0.1 + 带心跳/日志的小服务器。
- F/S/M 调试键部署期裸露无 `?debug=1` 门控（S 在 kiosk 还会往本机下载 PNG）；Python 每帧 new 3.7MB SRCALPHA Surface + 每帧字体光栅化（旧 4.6 项）。

### 5.5 时钟与其他

- Python 全链路 `time.time()` 墙钟：**回拨**时 swipe 窗口 dt 兜底 1e-3、正常位移算出 ~16.7/s 假高速可致假齐发（污染持续到墙钟追回）；前跳反而安全（cutoff 清空 hist）；喂 MediaPipe 的非单调时间戳还可能直接抛错杀线程。Web performance.now() 单调无此问题。建议两版统一单调时钟。
