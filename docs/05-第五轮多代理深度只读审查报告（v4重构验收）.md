## 三、本轮新发现问题（v4 新代码引入/遗留放大项）

> F-1–F-17 为代码取证 + 时序推演（触发条件可按描述复现，其中 F-10 经 node 实测、F-7 经 fontTools 实证）；V-IMG-* 为截图实证（§3.2）。自动化测试面已全部跑绿（方法学第 2 条），下列问题均不属于"测试失败"类，而属于并发健壮性、观感参数与部署完备性范畴。

### F-1 🔴 自愈路径接成稳态自杀环：restart 不可重入 + ended 级联 + devicechange 监听累积 + ok 不清 3s 定时器 + landmarker/流泄漏（代理复核后升级为 🔴）
**位置**：`tracking.js:117-127（restart）、148-164（landmarker/stream/video 每次 start 新建、从不 close）、166-172（监听注册）、216-232（catch/stalled 恢复发 ok）`；`main.js:58-81（health 处理：ok 分支直接 return，不清 _autoTimer；retry 按钮显隐不复位）`。
**机理（两条独立复核代理一致结论，并对双 rAF 后果做了修正）**：
1. `restart()` 无重入门；`track.stop()` 异步派发 ended，而 ended 处理器（166-169）无条件再调 restart()——每次主动重启排队触发下一次。
2. `navigator.mediaDevices.addEventListener('devicechange', …)` 每次 start() 累积、从不移除；N 次重启后一次插拔触发 N 路 restart。
3. **N1（🔴，交互脑代理时序推演）**：UI 的 3s 自动重启定时器（main.js:76-78）在 health 回 ok 时**从不清除**（ok 分支 60 行直接 return，全仓无 clearTimeout）。时序：T0 ended→遮罩+定时器→T0+1.2~2s 重连成功发 ok 遮罩撤，**定时器仍挂着**→T0+3s 对健康流调 restart→stop 派 ended→再重启→再挂定时器……形成约每 3s 一次的稳态循环，永不收敛；单帧推理 catch 与 stalled 自恢复走同一闭环；手动点"重试"也不撤在途定时器（双 restart 并发）。
4. **N3（🟠）**：restart 只 stop "调用当时"的 this.stream；并发重启中后醒的一路 stop 发生在新流诞生之前，**先成功的流成为活体孤儿（相机灯常亮、占设备，后续 getUserMedia 在 Windows 上易 NotReadable）**；旧 HandLandmarker 被覆盖从不 `.close()`（grep 零命中），GPU delegate 还各持 WebGL 上下文（浏览器上限约 16），3s 循环把泄漏拉到每周期 1–2 个，7×24 慢性衰竭。
5. 双 rAF 的后果修正（交互脑代理证伪了"双速喂帧/假齐发"）：两条 loop 拿相同 rAF 时间戳、共用 video，帧门控（currentTime!==lastVideoTime，196-197）使每帧第二跳必跳过 detect——真实危害是双份 _publish（幂等无害）、N 路 getUserMedia 争抢与 N3 孤儿流/泄漏，而非双速喂帧。
**后果**：USB 抖动（展厅最高频故障）一旦发生且能自愈，系统反而进入每 3s 自杀循环并慢性耗尽相机/GL 资源；不能自愈则遮罩常驻。
**建议**：①health 回 ok/starting/restart 入口统一 clearTimeout(_autoTimer)，retry 按钮点击时同样撤定时器；②restart 加 generation 单调号 + 单飞守卫（旧代 start 结果全部丢弃）；③ended 处理器比对事件 track===当前流的 videoTrack 且非主动关闭（主动 stop 前置 quieted 标记）；④devicechange 只注册一次或 start 前先 remove；⑤覆盖 landmarker 前 `await old?.close()`，替换 video 前 pause+srcObject=null 旧元素（N7.2：debug 预览窗在 restart 后永久挂旧 video）。

**位置**：`tracking.js:216-221（catch→onHealth reconnecting，每失败帧都发）`、`main.js:76-78（3s 定时器 restart）`。

### F-9 🟡 ideal 1280×720 实际分辨率不可见，palmSize 的 4:3 校正系数 0.75 在 16:9 下失配
**位置**：tracking.js:159-161（无 videoWidth 上报）、tracking.js:81-85（palmSize 仍乘 0.75）。
**机理**：
1. ideal 不满足时浏览器可静默降给 640×480，HUD/health/CSV 都不记录实际分辨率，现场掌宽表（§6.4）口径无法核对。
2. `palm=hypot(dx, 0.75·dy)` 的 0.75 是 4:3（H/W=0.75）时把纵向归一化距离折成横向尺度的系数；16:9 正确系数 = H/W = 9/16 = 0.5625。沿用 0.75 使纵向手掌尺度被高估最大 33%（0.75/0.5625），lockMaxPalm=0.40 的物理触发阈值变小（更易被判"凑近镜头"拒绝）——方向偏安全但尺度失真；若浏览器回落 4:3 又恰好应取 0.75。
**建议**：首帧后读取 video.videoWidth/Height：①写入 health/debug HUD 与标定 CSV；②按实际宽高比动态计算 y 折系数（或掌尺度直接用像素/帧宽，彻底归一化）。
**补充（需求复核代理推演，需重算定标）**：触发阈值本身也各向异性——`speed=hypot(vx屏宽,vy屏高)` 是混合单位，16:9 下纯竖向动作的归一化速度是同物理速度纯横向动作的 1.78 倍；4m/HFOV60 时 swipeHi=0.75 折算物理线速度：横向需 ≈3.46 m/s、竖向仅需 ≈1.95 m/s（21:9 画布进一步放大竖向敏感度，ideal 回落 4:3 时方向角变 36.9°）。Python 4:3 口径采得的手速分位不能直接给 16:9 部署用。建议阈值侧也做物理尺度归一（速度按物理宽/高或模型内像素/秒计），并在部署宽高比下重采 swipeHi 分位。
**方法学更正（需求复核代理）**：模型内像素 = 掌宽物理占比×192，**只与 HFOV/距离有关、与采集分辨率无关**——把采集从 640 升到 1280 仅使采集像素翻倍，模型输入仍是缩放后的 192，**对 BlazePalm 检测率零增益**；§6.4 表"模型内 px 翻倍"表述有误（采集 px 翻倍、模型内 px 不变），3–5m 检出率的唯一解仍是窄角 HFOV/中心裁剪（光学放大），而非提分辨率。

2. **齐发拖尾池"鬼剑气"（🟡中，01:46 版部分缓解）**：burst 重置 10 条拖尾时只 deactivate/reset 几何但**不清 `tr.user.idx`**（volley.js:140-143）；未被新领头 pop 走的空闲拖尾若 idx 仍指向上一记 FIRE/RETURN 旧剑，会被 290-315 行用 stale idx 重新激活——新齐发头约 0.6s 内最多 10 条鬼剑气在归阵剑身上重新生长（01:46 版在淡出退役处补了 `user.idx=-1; reset()`（297 行），残留窗口从"下次 burst 前"缩到 0.6s，但 burst 重置点仍不清 idx、退役拖尾仍不立即回 trailFree）。建议：burst 重置时即 user.idx=-1、退役即回收进 trailFree。
3. **本命剑低速停拖尾后再加速闪出整条旧 ribbon（⚪-🟡）**：hero.js:150-153 速度≤1.2 只 `trail.deactivate()` 不 reset（对照 release() 路径是 deactivate+reset，hero.js:77-79）；重新加速时 activate 首帧 drawRange 仍是全长 27 节点旧坐标，陈旧剑气闪现约 0.45s 才被覆盖。建议低速停用 deactivate+reset。
4. **idleSweep 的前景 z 是死写（⚪，纠正文档/注释预期）**：volley.js:168 `sz=-2-rand*2` 仅 GATHER seek 消费（211），SWEEP 分支（248-253）vz 恒 0，"横扫过前景"的设计注释不会发生，横扫始终在远空环面。
5. **516 个隐藏实例 mode 默认 0=RING（⚪，F-14.2 的精确化）**：volley.js:34 Uint8Array 默认 0，构造时隐藏槽（i≥252）只置 scale=0/slot=-1 未标独立模式；主循环 RING 分支对它们执行 `_ringPos`（ringIdx 为 undefined→环径取值 undefined→**坐标/颜色写为 NaN**，因 scale=0 实际不可见，但每帧向 instanceMatrix/instanceColor 缓冲写 NaN）、切线归一化（NaN→q.identity 兜底）并 `counts.ring++`，空闲时 counts.ring 恒为 768。当前 HUD 只用 ringTotal/counts.fire 暂不穿帮。建议：隐藏槽 mode=5(HIDDEN) 并 continue，mesh.count 收到实际在用上限。
6. **hero.release() 未清速度（⚪，与文件头"释放清速"注释不符）**：hero.js:76-80 只清拖尾；gone 态 roll 仍吃残留速度、fade 窗内朝向可能错一帧（残留经弹簧衰减已小，症状轻微；summon 时才清零）。建议 release 内 vx=vy=vz=0。

### F-17 🟡 NoiseEffect 构造签名用错：颗粒按 SCREEN 强度 1 生效，设计的 OVERLAY 0.05 从未生效【主控 vendor 源码核实】
**位置**：`postfx.js:34`（`new NoiseEffect(BlendFunction.OVERLAY, FX.grain)`）；vendor 实际签名为 `constructor({ blendFunction = SCREEN, premultiply } = {})`（postprocessing/index.js:8251），不接受位置参数，第二个参数（FX.grain=0.05）被直接丢弃；数字作 options 解构失败→回退默认 SCREEN，blendMode.opacity 默认 1（index.js:2452-2455）。
**后果**：全屏噪点 shader（每帧每像素 0..1 随机值）实际以 SCREEN、opacity=1 接入（设计为 OVERLAY 0.05，强度差 20 倍且混合模式不同）；静态截图中暗场可见细颗粒（与天空 shader 的 bayer dither 叠加，单帧不易分辨严重度），**动态下预期为明显闪烁雪花**，需录屏确认。ToneMapping/Vignette 构造签名正确（options 对象）不受影响。
**建议**：改为 `const noise = new NoiseEffect({ blendFunction: BlendFunction.OVERLAY }); noise.blendMode.opacity.value = FX.grain;`，改后录屏确认颗粒强度。

### 6.3 渲染管线与显存（架构复核代理重算，静态推演【待真机实测】）
- 管线：RenderPass（场景，含 SelectiveBloom 所需 stableDepth + DepthPass 额外深度绘制）→ EffectPass(SelectiveBloom，独立，因 DEPTH 属性不可合并) → EffectPass(Vignette+Noise OVERLAY 0.05，**注：Noise 构造签名误用见 F-17**) → EffectPass(ACES Tonemap + 输出 sRGB 转换，pmndrs 默认 colorSpaceConversion 开启，vendor:428-436)。
- RT 清单（代理逐项核 vendor 默认参数）：主双缓冲 HalfFloat（RGBA16F 8B/px + Float depthTexture 4B/px，×2）+ composer stableDepth RT（RGBA8+Float depth）+ SelectiveBloom DepthPass RT（selection 层重绘，非全场景）+ renderTargetMasked（HalfFloat）+ LuminancePass **全分辨率 HalfFloat** + 8+7 级 mip 链（约 0.67 全幅）+ Bloom 遗留 Kawase RT（0.5 幅）。
- 估算（架构代理重算，修正主控初版低估）：1080p/dpr≤1.75（≈2.0MP）约 **120–150MB**；封顶 3200×1800（5.76MP）约 **350–420MB**（主控初版 120–200MB 漏计 LuminancePass/masked/stableDepth）；旧链 1.2GB 风险仍数量级解除，但展厅低配集显（共享显存 512MB–1GB 档）需实测，建议目标机 chrome://gpu + 显存计数纳入 P2。
- 封顶逻辑验证（main.js:24-28）：dpr=min(devicePixelRatio,1.75)，scale=min(1,3200/(长边·dpr))，**下限 0.6 会反杀封顶**：8K（长边 7680、dpr1）时 scale=0.417 被 Math.max(0.6,·) 抬回 0.6 → 实际 4608 长边、超封顶 44%（显存 ×2.1）；4K TV（dpr=1）正常封到 3200×1800；1080p 原生。
- 残留：RT depthBuffer 不可关（SelectiveBloom 需要，合理）；软件渲染（WARP/SwiftShader）无检测告警；contextlost 无监听；SelectiveBloom 对透明加色发光体覆盖缺口（F-12）；fovKick 期间 screenToWorld 仍按 BASE_FOV 算（瞬态约 3.5% 映射偏差，⚪）。
